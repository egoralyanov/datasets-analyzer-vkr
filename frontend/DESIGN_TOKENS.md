# Дизайн-токены — «scientific / archive»

> Спринт 5, Phase 1. Файл фиксирует **визуальный язык** редизайна: палитру,
> типографику, шкалы отступов, радиусов, теней и границ. Это **спецификация** —
> не реализация. На этой фазе никакой код, конфиги и стили не меняются.
>
> Когда будем имплементировать (Phase 2+), эти значения переедут в
> `tailwind.config.js` (theme.extend.colors / fontFamily / spacing /
> borderRadius / boxShadow) и в CSS-переменные в `index.css`.

---

## 0. Эстетическое направление

**Scientific / Archive** — визуальный язык научного журнала второй половины
XX века в сочетании с архивным/каталожным документом.

**Референсы (для понимания тона, не копировать буквально):**

- Annalen der Physik, Communications of the ACM, Bell System Technical Journal — типографическая иерархия с колонтитулами и нумерацией параграфов.
- Edward Tufte — дисциплина данных, минимум «графического мусора».
- Стиль карточек библиотечного каталога — ровные ряды, моноширинные идентификаторы, hairline-рули между строк.
- Лоу-контрастные палитры технических изданий: индиго-чернила на кремовой бумаге, кирпичные отметки.

**Чего избегаем:**

- Покрывной tech-blue типа `#2563EB` — слишком «SaaS», теряет научный тон.
- Неоновые зелёные/жёлтые акценты, gradient-карточки, glassmorphism.
- Скруглённые «pill»-формы и тяжёлые тени, имитирующие глубину.
- Inter / Roboto / system-stack как основной шрифт интерфейса — банально и не отражает направление.
- Иконки в стиле «AI-illustration» (объёмные, цветные).

Все значения — sRGB hex. Ниже — конкретные шкалы для использования в Tailwind

## 2. Типографика

### 2.1. Шрифтовая система

Все три семейства — **IBM Plex** (open source, SIL OFL 1.1):

- **`IBM Plex Serif`** — заголовки, нарративный текст (объяснения правил, описания), длинные блоки. Строгий «учебный» серифный шрифт, разработан IBM Brand Experience и Bold Monkey, идеально подходит под scientific-тон.
- **`IBM Plex Sans`** — UI-chrome: навигация, кнопки, лейблы, формы, таблицы.
- **`IBM Plex Mono`** — технические идентификаторы, цифры, метрики, имена колонок, пути файлов, размеры в байтах, JSON-контекст, идентификаторы анализа.

Подключение: через `@fontsource/ibm-plex-serif`, `@fontsource/ibm-plex-sans`,
`@fontsource/ibm-plex-mono` (npm-пакеты, локальное самохостинг через Vite — не
ходим во внешние CDN). Веса: 400, 500, 600, 700 для Sans/Serif; 400, 500 для
Mono.

**Fallback-стек** (на случай не загрузившихся шрифтов):

```css
--font-serif: "IBM Plex Serif", "Source Serif 4", Georgia, "Times New Roman", serif;
--font-sans:  "IBM Plex Sans", "Source Sans 3", system-ui, -apple-system, sans-serif;
--font-mono:  "IBM Plex Mono", "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
```

### 2.2. Иерархия размеров (rem; 1rem = 16px)

| Токен | Размер | Line-height | Letter-spacing | Применение |
|---|---|---|---|---|
| `text-display` | `2.25rem` (36px) | `1.15` | `-0.02em` | Заголовок страницы (Serif 600) |
| `text-h1` | `1.75rem` (28px) | `1.2` | `-0.015em` | Главный заголовок секции (Serif 600) |
| `text-h2` | `1.375rem` (22px) | `1.3` | `-0.01em` | §-заголовок (Serif 500) |
| `text-h3` | `1.125rem` (18px) | `1.4` | `0` | Подзаголовок (Sans 600) |
| `text-body` | `0.9375rem` (15px) | `1.55` | `0` | Основной текст (Serif 400 для нарратива; Sans 400 для UI) |
| `text-sm` | `0.8125rem` (13px) | `1.5` | `0` | Caption, мета, подписи к графикам (Sans 400) |
| `text-xs` | `0.75rem` (12px) | `1.4` | `0.04em` | Лейблы, бейджи **uppercase** (Sans 500) |
| `text-mono-md` | `0.875rem` (14px) | `1.5` | `0` | Технические значения (Mono 400) |
| `text-mono-sm` | `0.75rem` (12px) | `1.45` | `0` | Бейджи кодов правил, ID (Mono 500) |

**Правило раздачи семейств:**

- Заголовки `display`/`h1`/`h2` — **Serif** (Plex Serif).
- Заголовки `h3` и UI-элементы — **Sans** (Plex Sans).
- Body нарративного контента (описания правил, объяснения рекомендации) — **Serif**.
- Body UI (кнопки, формы, лейблы, навигация) — **Sans**.
- Любая числовая метрика, идентификатор, имя колонки/файла, JSON-контекст — **Mono**.

Для бейджей и лейблов используется **uppercase + tracking** (см. `text-xs`) —
типографический акцент архивных каталогов.

### 2.3. Веса

- **400** — body (Sans + Serif).
- **500** — мета-лейблы Sans (uppercase tracking).
- **600** — заголовки h1–h3, активные ссылки.
- **700** — `display` уровень, акценты в Serif.

В Mono используем 400 / 500.

## 3. Шкала отступов (spacing)

Стандартная Tailwind-шкала на основе `0.25rem` подходит без изменений. Но в
визуальном языке закрепляем **предпочтительные** значения (используем их, а не
произвольные):

| Токен | Размер | Применение |
|---|---|---|
| `space-1` | 4px | внутри бейджей, между иконкой и текстом |
| `space-2` | 8px | минимальный gap в таблицах |
| `space-3` | 12px | gap между элементами строки |
| `space-4` | 16px | базовый отступ внутри строки flag-row, padding кнопок |
| `space-6` | 24px | вертикальный gap между параграфами body |
| `space-8` | 32px | межсекционный отступ внутри страницы |
| `space-12` | 48px | отступ вокруг §-заголовков |
| `space-16` | 64px | разделение крупных блоков (header → main, main → footer) |

Шкалу 8/16/24/32/48/64 принимаем как «костяк». 12 — переходный, для строчных
композиций.

**Поля контейнера страницы:** `max-width: 1100px` (узкий «журнальный»
column-width); `padding-x: 32px` mobile-tablet, `padding-x: 64px` desktop.
Узкий контейнер усиливает ощущение страницы научной статьи.

## 4. Радиусы (radii)

Минимизируем. Архивный/научный документ почти всегда имеет прямые углы.

| Токен | Размер | Применение |
|---|---|---|
| `rounded-none` | 0 | таблицы, карточки секций, drop-zone, header, footer |
| `rounded-xs` | 2px | кнопки, инпуты, бейджи |
| `rounded-sm` | 3px | модалки, tooltip (предельный максимум) |

Полностью убираем `rounded-md`/`rounded-lg`/`rounded-xl`/`rounded-full`.
Аватары, если будут — квадратные (или с `rounded-xs`).

## 5. Тени (shadows)

Почти не используем. Глубина и отделение элементов — через **границы**, не
через тени.

| Токен | CSS | Применение |
|---|---|---|
| `shadow-none` | `none` | по умолчанию для всего |
| `shadow-overlay` | `0 2px 8px rgba(28, 25, 31, 0.08)` | модалка, дропдаун, popover (единственный кейс) |

Тени `shadow-sm`/`shadow-md`/`shadow-lg` НЕ используем. Если возникает соблазн
поставить тень — лучше поставить 1px-границу.

## 6. Границы (borders)

Главный инструмент структурирования.

### 6.1. Толщины

| Токен | Толщина | Цвет (default) | Применение |
|---|---|---|---|
| `border-hairline` | 1px | `paper.300` (#D2CCBE) | стандартные обводки таблиц, карточек, инпутов |
| `border-strong` | 1px | `paper.400` (#A89F8E) | усиленные разделители, выделенные строки |
| `border-rule` | 3px solid | `ink.700` или semantic.500 | левая «рулевая» полоса для строки flag, выделенный блок |
| `border-double` | 3px double | `paper.400` | разделение крупных секций (после header, перед footer) |

Для активных состояний (focus на инпуте, выбранная строка) — обводка `1px solid
ink.700` ИЛИ нижняя `border-bottom: 2px solid ink.700` (типографский подчёрк).

### 6.2. Где обязательно

- **Header**: нижний `border-double 3px paper.400`.
- **Все таблицы**: `border-hairline` между строк (border-collapse + 1px-bottom на каждом `tr`).
- **Карточки секций (§1, §2...)**: внешняя `border-hairline`, без скруглений и теней.
- **Quality flag rows**: левая `border-rule` 3px цвета severity, нижний `border-hairline`.
- **DropZone**: внешняя `border-hairline` + декоративная внутренняя «двойная рамка» 1px на 6px отступе.

## 7. Принципы (manifesto)

1. **Таблицы и сетки приоритетнее карточек.** Информационная плотность — добродетель. Где сейчас «карточка с тенью» — там должен быть ряд таблицы или ruled-строка.
2. **Границы, а не тени.** Глубина выражается через тонкие линии (`paper.300`), а не drop-shadows. Единственное исключение — overlay (модалка/popover).
3. **Моноширинный — для всего технического.** Любая цифра, идентификатор, имя колонки, имя файла, путь, размер, ID анализа — в `IBM Plex Mono`. Это сразу читается как «машинно-сгенерированное» и отличает от нарратива.
4. **Сериф — для нарратива, санс — для UI.** Описания правил, объяснения рекомендации, заголовки секций — `Plex Serif`. Кнопки, навигация, формы, лейблы — `Plex Sans`. Это типографическая иерархия научной статьи: «текст vs аппарат».
5. **Кремовый фон, не белый.** Базовый фон — `paper.50` (#FAF8F4). Тёплый сдвиг снимает «экранность» и попадает в archive-тон. Чисто-белые поверхности не используем.
6. **Прямые углы.** Скругления почти везде нулевые; кнопки/инпуты — 2px максимум. Скруглённые «pill»-бейджи и круглые иконки несовместимы с направлением.
7. **Семантические цвета — отметки, а не заливки.** Critical/warning/info/success появляются как 3px-руля слева, иконка, цвет текста бейджа, лёгкий тинт фона строки (`*-50`). Никаких «красных кнопок» во весь блок.
8. **Структурная нумерация.** Секции страницы помечаются префиксами `§1`, `§2` (как параграфы научной статьи); правила и flags — своим code-bademont в Mono. Это даёт читателю «навигационные крючки» и поддерживает archive-tone.

## 8. Применение к нашим компонентам

Ниже — **направления** редизайна для существующих компонентов фронта. Это не
ТЗ Phase 2 целиком, а каркас, чтобы зафиксировать общий язык. Конкретные
файлы трогаем в следующих фазах.

### 8.1. Header (`components/layout/Header.tsx`)

**Сейчас:** простой flex-блок «Анализатор / навигация / username / Выйти» на
slate-фоне.

**Станет:**

- Фон — `paper.50` (как у страницы); снизу `border-double 3px paper.400`.
- Слева — логотип «АНАЛИЗАТОР» в `Plex Serif 700`, размер `text-h1`, под ним мелкими `text-xs uppercase tracking` подзаголовок «ИНТЕЛЛЕКТУАЛЬНАЯ СИСТЕМА АНАЛИЗА НАБОРОВ ДАННЫХ».
- В центре/справа — навигация: ссылки в `Plex Sans 500 uppercase text-xs tracking-wider`, разделены тонкой `|` или вертикальными hairline-руллями. Активная ссылка — подчёркнута 2px `ink.700` (без bg-fill).
- Username — в `Plex Mono 500 text-mono-sm`, рядом «ВЫЙТИ» как plain-link.
- Никаких иконок в навигации (или строго line-стиль `lucide`, размер 14px, `paper.500` цвета).

ASCII-схема:

```
┌──────────────────────────────────────────────────────────────────────────┐
│  АНАЛИЗАТОР                  ЗАГРУЗИТЬ │ ИСТОРИЯ │ АДМИН │ ПРОФИЛЬ        │
│  ИНТЕЛЛЕКТУАЛЬНАЯ СИСТЕМА...                                              │
│                                            user@example.com   [ВЫЙТИ]    │
╞══════════════════════════════════════════════════════════════════════════╡  ← double rule
```

### 8.2. Карточки качества данных (`components/analysis/QualityFlags.tsx`)

**Сейчас:** цветные карточки `bg-red-50/border-red-200` (red/amber/blue),
группировка по severity, expandable «Подробнее».

**Станет — табличная композиция, не карточки:**

- Группировка по severity сохраняется, но как `<section>` с заголовком `§N.N <severity_uppercase>` (`КРИТИЧЕСКИЕ`, `ПРЕДУПРЕЖДЕНИЯ`, `ИНФОРМАЦИЯ`).
- Каждый flag — `<row>` (или `<tr>` если возьмём настоящую таблицу) с:
  - Левая полоса `border-rule` 3px соответствующего семантического цвета (`critical.500` / `warning.500` / `info.500`).
  - Бейдж `CRIT` / `WARN` / `INFO` в `Plex Mono 500 text-mono-sm` цвета `<severity>.700`, без bg-fill.
  - Code правила в `Plex Mono` рядом с бейджем (например `MISSING_VALUES`).
  - Описание в `Plex Serif 400 text-body`.
  - Лёгкий тинт фона строки `<severity>.50` (опционально, только для critical).
  - «Подробнее» — текстовая ссылка (`underline ink.700`), при раскрытии — definition-list с key/value, value в Mono.
- Между строк — `border-hairline` снизу.

ASCII-схема одной строки:

```
║  CRIT  TARGET_LEAKAGE          Колонка `passenger_id` коррелирует с target r=0.97   [Подробнее]
║                                ───────────────────────────────────────────
║                                column     passenger_id
║                                r          0.97
║                                threshold  0.95
└──────────────────────────────────────────────────────────────────────────────────────────────
```

(`║` слева — это `border-rule` 3px `critical.500`.)

### 8.3. Drop-zone загрузки (`components/upload/FileDropZone.tsx`)

**Сейчас:** dashed-border квадрат, blue-акценты, иконка облака.

**Станет — «архивная карточка»:**

- Внешняя рамка — `border-hairline` (1px solid `paper.300`), углы прямые.
- Внутренняя декоративная «двойная рамка» через CSS — `box-shadow: inset 0 0 0 1px paper.300` со смещением 6px (или повторная `<div>`-обёртка).
- В четырёх углах — символы `+` в `Plex Mono`, в `paper.400` (мета крестики, как метки выравнивания на типографских формах).
